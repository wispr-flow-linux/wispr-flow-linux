## Conventions to keep

- Branch names `fix/<issue>-desc` or `feature/<issue>-desc`; squash-merge
  with `(#N)` in the subject and a written body (what, why, what was
  verified, `Fixes #N`, co-author lines); `Co-Authored-By: Claude
  <claude@anthropic.com>` trailer on commits. Issues and PRs are short and
  plain (CLAUDE.md, "Issues, PRs, and commits"); PR bodies end with the
  `Co-Authored-By: Claude Fable 5.1 <noreply@anthropic.com>` line. Comments
  carry no trailer.
- **The hooks are live.** `.claude/settings.json` runs
  `.claude/hooks/pre-pr-lint.sh` before every `git push` issued from the
  Bash tool: the CI shellcheck line, codespell over tracked files,
  actionlint on changed workflows, and `bats tests/*.bats` when a `.sh` or
  `.bats` file changed against `main` (about 45 s). A failure blocks the
  push with the output; fix and push again. `session-start.sh` prints the
  tool status at startup.
- To land a fork PR: `git fetch origin pull/N/head:pr-N`, work in a
  `git worktree` under the session scratchpad, `git merge origin/main`,
  edit, run `bats tests/*.bats`, the CI shellcheck line
  (`git grep -l '^#\( *shellcheck \|!\(/bin/\|/usr/bin/env \)\(sh\|bash\|dash\|ksh\)\)' -- '*.sh' | xargs shellcheck -x --severity=warning`),
  `codespell`, `actionlint`, `tests/test-patch-stage.sh <resources>` for
  any patch change, then push to the contributor's branch under maintainer
  edits and `gh pr merge N --squash --subject ... --body-file -`. A
  cherry-pick keeps the author's commit; put your own additions in a second
  commit.
- `tests/test-patch-stage.sh` uses `extract/` when it holds the pinned
  version, else downloads the pinned installer into
  `build-linux/downloads`. A worktree has no `extract/`, so pass the main
  checkout's `extract/nupkg/lib/net45/resources` as the argument (about
  40 s). Pristine main bundles for grepping:
  `build-linux/app.asar.contents/.webpack/main/index.js.orig` (1.6.897, in
  the main checkout) and an asar extract of
  `extract-1.5.789/nupkg/lib/net45/resources/app.asar` into the scratchpad.
- Resolve conflicts with line-anchored markers (`^<<<<<<< `, `^=======$`);
  same-block appends in `build-linux.sh`, `MARKERS=(`, `MARKER_SAMPLES`
  and the `tests/README.md` table are keep-both. `CHANGELOG.md` Unreleased
  conflicts when two PRs add at the top of the same list; keep main's
  bullets first. After a rebase, `git push --force-with-lease` re-triggers
  the PR run; `gh pr checks` sometimes says "no checks reported" while
  `gh run list --branch <b>` is authoritative, and
  `gh workflow run ci.yml --ref <b>` dispatches a run by hand.
- A stacked PR says so in its first line. `ci.yml` only triggers on PRs
  against `main`, so a PR based on another branch gets its gates with
  `gh workflow run ci.yml --ref <branch>`; after the base lands,
  `git rebase --onto origin/main <old-base-sha> <branch>`, force-push, and
  `gh pr edit N --base main`.
- Bash: tabs, 80 cols, `[[ ]]`, no `set -e` (except the existing
  `scripts/patches/` files, which use `set -euo pipefail` and 2-space indent
  as house style there; `scripts/build-linux.sh` is 2-space too). A comment
  inside a workflow `run:` block must not start with the word
  `shellcheck`: shellcheck reads it as a directive and actionlint fails.
- `codespell` scans `.claude/memory/` too (`check-hidden = true`), and it
  flags two-letter minified identifiers. An inline `# codespell:ignore
  <word>` on the same line works with a lowercase word. In prose, describe
  the identifier instead of naming it. Locally, `extract-1.5.789/` trips
  it; the hook scans tracked files only, and a bare run wants
  `--skip='extract-1.5.789'`.
- `grep` is shadowed by a ugrep wrapper in this shell; use `/usr/bin/grep`
  when a byte-count or `-o` result matters. `$TMPDIR` is unset; use the
  session scratchpad path. The scratchpad is on a different filesystem from
  the repo, so `cp -al` across them fails; hardlink copies of an AppDir go
  under the repo's gitignored `build-linux/` and are removed after.
- The Bash tool's shell has job control on: a `cmd &` is its own process
  group and `$!` is its pgid. `setsid cmd &` forks, so `$!` is a parent that
  exits at once; read the group with `ps -o pgid= -p <pid>` instead.
  `pkill -f <pattern>` kills the tool's own shell when the pattern text is
  anywhere in that command line, including as a path literal; bracketing
  one letter of the regex only stops it matching its own text. Prefer
  `kill -- -<pgid>` and a `pgrep` that excludes `$$` and `$PPID`.
- Any desktop smoke launch uses an isolated profile and says so first.
  Recipe: hardlink-copy the AppDir into `build-linux/verify-<x>`, drop the
  launcher library under test into `usr/lib/wispr-flow/`, then
  `env HOME=<iso>/home XDG_CACHE_HOME=<iso>/cache XDG_CONFIG_HOME=<iso>/config XDG_DATA_HOME=<iso>/data XDG_STATE_HOME=<iso>/state <flags> "$A/AppRun" &`,
  poll `<iso>/cache/wispr-flow/launcher.log` for `Helper service is ready:
  true`, then inspect (`lsof +E -a -U -p <main pid>` shows the display
  socket; a python-xlib walk of the X tree finds Wispr-class windows,
  including the unmanaged pill), then `kill -TERM -- -<pgid>`, `kill
  -KILL`, and `pgrep -cx wispr-flow` must read 0. A fresh profile shows no
  login and opens no managed window, so window scans need the tree walk,
  not `_NET_CLIENT_LIST`. The isolated HOME ends up with `~/Library/...`;
  that is #100, not a leak from the run.
- `build.log` in the repo root is untracked scratch; leave it alone.
- A per-job CI log needs
  `gh api --allow-escape-sequences repos/<owner>/<repo>/actions/jobs/<id>/logs`
  while the run is in progress; `gh run view --log-failed` works once it
  completes, and a bats failure that prints every `ok` but exits 1 is a
  teardown error (look for a `bats-exec-test` line).
