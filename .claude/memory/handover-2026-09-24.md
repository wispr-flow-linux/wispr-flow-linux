## Conventions to keep

- Branch names `fix/<issue>-desc` or `feature/<issue>-desc`; file the
  issue first when none exists (short, plain, what is wrong and what
  should be true). Squash-merge with `(#N)` in the subject and a written
  body (what, why, what was verified, `Fixes #N`, co-author line);
  `Co-Authored-By: Claude <claude@anthropic.com>` on commits, `Co-Authored-By:
  Claude Fable 5.1 <noreply@anthropic.com>` at the end of PR and issue
  bodies. Comments carry no trailer.
- **The hooks are live.** `.claude/hooks/pre-pr-lint.sh` gates every
  `git push` from the Bash tool on the CI shellcheck line, codespell,
  actionlint and (on a shell change) `bats tests/*.bats` (about 60 s now,
  226 tests).
- **Two PRs adding to the same CHANGELOG list conflict** at merge time. `gh
  pr merge` then refuses; fetch the branch into a worktree, `git rebase
  origin/main`, delete the three marker lines (main's bullets are first),
  `--force-with-lease`, merge again. Do not chain `git branch -D` after a
  merge command that can fail; this session lost a local branch that way
  and recovered it from `origin/`.
- **Mutation checks restore from a copy, never `git checkout`.** Twice
  this session a `git checkout <file>` meant to undo a mutation also threw
  away uncommitted edits to the same file. Copy the file aside first.
- To land a fork PR with maintainer edits: `git fetch origin
  pull/N/head:pr-N`, worktree under the session scratchpad, edits as a
  second commit on top of the author's, `git push
  https://github.com/<fork>.git pr-N:<branch>` (the fork must allow
  maintainer edits; #102's did), then `gh pr merge N --squash`.
- `tests/test-patch-stage.sh <resources>` takes about 60 s and now runs
  the tripwire pass first; 13 checks. A worktree has no `extract/`, so
  pass a resources dir (`<x>/nupkg/lib/net45/resources` with `app.asar`
  and `app.asar.unpacked` beside it). Pristine bundles for grepping:
  `build-linux/app.asar.contents/.webpack/main/index.js.orig` is 1.6.897
  in the main checkout after a build; an asar extract of the 1.6.937
  installer (`build-linux/downloads/wispr-flow-setup-1.6.937.exe`, cached)
  goes under the scratchpad.
- A local AppImage build of a branch takes under a minute with the
  downloads cached: copy `build-linux/downloads/` and `helper-bin/` into
  the worktree, `./build.sh --build appimage`, then
  `tests/test-artifact-appimage.sh build-linux/appimage` under `env
  HOME=<iso>/home XDG_CONFIG_HOME=... XDG_DATA_HOME=... XDG_STATE_HOME=...`
  (the harness only redirects the cache dir; without the rest the launch
  writes your real `~/Library`). It reaches helper-ready with a real
  backend under Xvfb.
- Bash: tabs, 80 cols, `[[ ]]`, no `set -e` (except `scripts/patches/`,
  `set -euo pipefail` and each file's own indentation; `_lib.sh` is tabs).
  A comment inside a workflow `run:` block must not start with the word
  `shellcheck`.
- `codespell` scans `.claude/memory/` (`check-hidden = true`) and flags
  two-letter minified identifiers; describe the identifier in prose.
  Locally `extract-1.5.789/` trips it; the hook scans tracked files only.
- `grep` is shadowed by a ugrep wrapper in this shell; use `/usr/bin/grep`
  when a count or `-o` result matters. `$TMPDIR` is unset; use the session
  scratchpad. The Bash tool blocks a bare `sleep`; poll with an
  `until ...; do sleep; done` loop or the Monitor tool.
- The Bash tool's shell has job control on: `pkill -f <pattern>` kills the
  tool's own shell when the pattern text is in its command line. Prefer
  `kill -- -<pgid>`.
- `build.log` in the repo root is untracked scratch; leave it alone.
- `tests/test-artifact-appimage.sh` sends `--doctor` output to
  `/dev/null` and redirects `XDG_CACHE_HOME` to a temp dir, so neither
  the doctor lines nor the launcher log survive the run. To see a doctor
  line, run the built AppImage's `--doctor` yourself under the isolated
  env. To prove an app opened a migrated database rather than a fresh
  one, add a probe table to the source copy with `sqlite3` first.
  (`sqlite3` is on PATH from the Android SDK here.)
- bats test bodies run with errexit, so a launcher function that tolerates
  a failing command (`rmdir` on a non-empty dir) needs `|| true` on it or
  the test aborts inside the function. `log_message` writes only `$1`, so
  pass it one string.

## Open decisions for the maintainer (do not decide these yourself)

- **The Wayland pill strategy:** GNOME-extension-only input shaping (review
  the five stacked helper PRs #16–#20, cut v0.1.3) versus the
  `WISPR_USE_X11=1` opt-in (#94) as the cross-compositor fallback. #78,
  #68, #67 and the reworked #73 all key off this. Recommendation on record
  (2026-09-22): do both, X11 opt-in first (done), and treat #78's title
  channel as compositor-neutral with the GNOME extension as its first
  consumer and a KWin script as the second.
- **#100's migration shape (#112 proposes "move"):** the launcher moves
  `~/Library/Application Support/Wispr Flow/*` into `~/.config/Wispr Flow`
  before Electron starts. It moves nothing while a SingletonLock exists or
  when any name would clash, and `rmdir`s the empty parents. The
  alternative is read-through with a doctor warning. On the maintainer's
  real profile nothing clashes (avatars, backups, the flow.sqlite trio),
  so the move would take all five entries and `~/Library` would go.

## Decided

- Publish gate: none. Automatic and fail-closed (2026-09-22, D-011). The
  bump pre-checks itself before committing and files an issue on red
  (2026-09-24, D-011 amendment). A bump that deserves a look gets a
  hand-pushed rc tag first, as 1.0.4 did.
- PR policy: duplicates close with credit, 30 days of silence allows a
  cherry-pick under maintainer edits or a close, stacked PRs say so, a patch
  names the bundle it was verified against (2026-09-22, D-012).
- A failed patch fails step 3 (2026-09-24, #105). Tripwires run on the
  pristine tree before the first patch and are skipped on a marked tree
  (2026-09-24, #108).
